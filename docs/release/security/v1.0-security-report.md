## Scope and supported boundary

This report covers the V1.0 standalone PHP Spoke, website client, shared
packages used by the Spoke, local administrator portal, local SQLite storage,
SMTP delivery, cron-invoked workers, private file boundary, release package,
manual upgrade, and paired rollback.

The candidate declares PHP 8.4 and 8.5, SQLite/PDO, `ext-zip`, HTTPS, PHP CLI
or equivalent hosting-panel access, and protected writable private storage as
its supported host capabilities. Node.js/npm and Composer are build-machine
requirements only; they are not required on the customer Spoke host.

V2 Enterprise Hub/Management Platform workload and tenant-isolation tests are
not part of this V1.0 candidate. V1.1 and V3 features are not part of this
candidate. The application cannot inspect an arbitrary hosting provider's
crontab; this report records application heartbeat evidence and the hosting
administrator remains responsible for scheduler configuration.

## Threat-model update

The release review covers these trust boundaries and data flows:

1. A visitor browser sends only approved form data to the local Spoke after
   same-origin/HTTPS resolution. The browser never receives SMTP settings,
   recipients, secrets, trusted proxy rules, or stored submissions.
2. Public resolution and submission endpoints accept untrusted origin,
   query, JSON, form-control, CAPTCHA, attempt-reference, and request-size
   input. Server-side validation, origin policy, rate limits, CAPTCHA policy,
   duplicate protection, and active-version checks remain authoritative.
3. The local administrator portal is authenticated and CSRF-protected. Every
   form, submission, delivery, export, Trash, backup, restore, maintenance,
   upgrade, and rollback action remains ownership-checked by the Spoke.
4. SMTP credentials remain in private secret storage. SMTP calls remain
   outside SQLite write transactions, and SMTP acceptance is recorded without
   claiming inbox placement.
5. Visitor submissions, recipient/configuration snapshots, delivery state,
   backups, exports, diagnostics, and operational data remain local to the
   Spoke. They do not cross into the Hub boundary in V1.0.
6. Private SQLite files, secrets, logs, diagnostics, exports, backups, release
   staging data, and runtime markers remain outside the public web root and
   are rejected by the release package boundary.
7. Upgrade and rollback operations require server-side administrator access,
   explicit package/archive paths, verified digests, private locks, bounded
   maintenance, and matching code/data checkpoints.

No new trust boundary, public route, credential, database schema, or external
service was introduced by Unit 19. The review found no changed boundary that
requires a new runtime security control.

## Residual risks and deliberate limitations

- Passing this report does not claim zero vulnerabilities or an independent
  penetration test.
- The application cannot inspect a provider's cPanel/system crontab directly;
  scheduler readiness is based on application-observed heartbeats and requires
  hosting-administrator confirmation.
- SMTP acceptance proves handoff to the configured SMTP server, not inbox
  placement or mailbox filtering.
- Unit 17 archives are plain ZIP files without encryption or password
  protection, as explicitly approved.
- The release supports the declared PHP/hosting matrix only; unsupported
  hosting layouts remain outside the compatibility claim.
- V2 Hub/Management Platform tenant and workload assurances are deferred to
  their own release gates.
