## 2. Scope, supported hosts, and exclusions

This gate covers release identity, packaging, the affected V1.0 boundaries,
Units 20–26, release documentation, and security evidence. It does not add
runtime product behavior, automatic upgrades, remote deployment, production DNS
changes, customer website changes, or customer data handling.

PHP 8.4 was verified locally. The project owner explicitly decided that PHP
8.5 supported-host verification is not required for this V1.1 release. The
authorized staging acceptance was confirmed as passed using synthetic data
only.

This is not an independent penetration test, a zero-vulnerability claim, a
universal hosting guarantee, or an inbox-placement guarantee.

## 3. V1.1 threat-model changes and trust boundaries

No new public route, visitor-data flow, authentication boundary, delivery
provider, database table, or runtime dependency was introduced by this gate.

Two release-blocking compatibility defects were corrected within their owning
boundaries:

1. The release manifest now declares compatibility from the V1.0 schema
   baseline `000016` through the current schema `000021`.
2. Backup restore now accepts the current schema `000021` and rejects future
   schema `000022` and above. Current-schema reconciliation is covered by an
   integration test.

The npm lockfile was also updated from `source-map-js` `1.2.1` to `1.2.2` in
response to a high-severity advisory. The dependency audit is now clean.
